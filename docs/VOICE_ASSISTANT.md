# AttackTrace voice assistant

The Copilot microphone records one user-initiated turn. The transcript appears in the composer for review. Recognized requests can navigate to a workspace page, focus a known asset, or show the Process Graph or Digital Twin. Other requests are sent to the evidence-grounded Copilot. The microphone never executes isolation, source switching, reset, lab changes, or other control actions. Existing on-screen permissions and confirmation remain in force.

AI & Voice settings at `/settings` select browser or server speech, voice, rate for browser synthesis, spoken reply summaries, and incident briefings. Spoken incident briefings are off by default and state uncertainty. A stop button cancels speech. These settings are stored in this browser; they are not synchronized across users or devices.

Browser speech recognition may use a browser-vendor service. Browser speech output uses available system voices. The Gemini server path uses the existing `GEMINI_API_KEY` **only on the backend**. It uses `gemini-3.5-transcribe` for a bounded push-to-talk recording and selectable Gemini Flash or Flash-Lite TTS for bounded speech output. The server limits recordings to 8 MB, responses to 400 characters, and requests to 12 per minute per authenticated user or local client. The server applies the same authentication, role, CSRF and API-key boundary as the rest of the private application. Audio and spoken text sent through this path reach Google; the UI discloses this before the provider is selected. Do not put the key in `VITE_*` settings.

The **Live voice chat** button in Copilot starts a separate two-way Gemini Live session. It streams microphone audio through the backend and plays Gemini's audio replies while displaying both transcripts. You can interrupt a reply, mute the microphone, or end the session; closing Copilot also releases the microphone. The panel lets you select a microphone and, where the browser supports output selection, a speaker before connecting. Microphone capture uses AudioWorklet; it requires a secure browser context. If a connection fails or the five-minute limit is reached, the panel explains why and offers a manual reconnect. The backend uses `gemini-3.8-live` with 16 kHz PCM input and 24 kHz PCM output. It keeps the API key server-side, rechecks private sessions, limits each session to five minutes and 10 MB of input audio, and limits concurrent sessions. The model can request a read-only lookup of current reported readings and incident hypotheses. It cannot invoke plant controls, simulation attacks, source changes, or analyst workflow writes.

Live voice is user-started and stops when the panel closes. It is not background listening or unrestricted voice automation. Spoken answers about attack origins are hypotheses; check the visible investigation evidence before acting. The Live API is a preview service, so availability and latency depend on Google. The existing microphone button remains a one-turn transcript workflow that lets the operator review text before sending it. Live audio and transcripts are sent to Google through the server and are not stored by AttackTrace as incident evidence.
